# 汇报主图优化提示词

## 目标

为《LLM 局部重调度方案验证报告》制作一张 16:9 汇报主图，让管理者在 10 秒内看懂：

1. Codex 不是替代整个调度系统，只处理决策树失败的困难窗口。
2. 真实 11:00–11:20、31 炉压力回放中，决策树为 30/31，Codex 为 31/31。
3. Codex 只改配 3 炉、保留 AP 原计划 28 炉，并且通过统一硬约束终检。

## 优化后的制图提示词

以宝钢钢包调度为背景，绘制一张 16:9、适合汇报投屏的“扰动后局部重调度闭环图”。只突出一个主线：`AP 预配基线 → 11:00 扰动 → 截取 11:00–11:20 局部窗口（31 炉）→ 决策树 AQ 30/31 → Codex 独立生成 AR 31/31 → 硬约束终检通过 → 恢复生产`。

图中明确 AP 是唯一共同基线，AQ 与 AR 两条线路独立；Codex 不读取 AQ。用一个醒目的结果区呈现 `决策树 30/31`、`Codex 31/31`、`改配 3 炉 / 保持 AP 28 炉`。用橙红色只标出“行车 2500 离线”和“决策树失败后 Codex 介入”，其余采用白底、深蓝线框、灰色辅助文字和绿色通过状态。删除 Frozen、人工、20 个事故卡片和长段解释，不使用营销式渐变或装饰图形。所有文案用短句，中文优先，保留 AP/AQ/AR、Codex、11:00–11:20 等必要技术字段。输出自包含 SVG/HTML，并导出 PNG 截图，供报告插图使用。

## 设计决策

- 视觉类型：流程图，主语义为“决策树失败后转入 Codex 的双线路分流”。
- 尺寸：`slide-16x9`，1600×900。
- 细节：`balanced`，7 个关键节点，避免把 20 类扰动挤进主图。
- 受众：`executive`，先看结果，再看流程；技术字段只保留必要的 AP/AQ/AR、时间和炉次数。
- 重点颜色：橙色只用于 Codex 介入路径；绿色只用于通过和恢复；其余使用白底、深蓝线框和灰色辅助文字。
- 数据边界：行车 2500 离线是受控压力输入，不表述为真实事故记录；Codex 结果是离线审计中的 Codex-authored proposal，`external_api_called=false`。
