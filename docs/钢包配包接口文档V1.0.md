# 钢包配包接口文档 V1.0

## 一、背景

钢包配包服务接收上游已经安排好的炉次计划、钢包资源、行车快照和位置映射，
通过确定性决策树生成钢包与行车的预配结果。

正常预配包由决策树执行，不调用大语言模型。突发扰动模拟使用独立的 LLM
Workflow；LLM 生成的候选方案仍必须通过硬约束校验，不能直接作为生产指令。

本文档按照当前本地 HTTP 服务的实际路由和返回结果编写。当前服务提供：

- 正式业务接口：正常预配包接口；
- 场景查询接口：供前端读取离线受控场景；
- 扰动模拟接口：供演示和联调使用，不等同于正式生产配包接口。

## 三、通用说明

### 1. Base URL

~~~text
http://127.0.0.1:4173
~~~

启动服务：

~~~bash
source .env.local
.venv/bin/python tools/serve_visualization.py --port 4173
~~~

### 2. 请求头

| 参数名 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| Content-Type | POST 必填 | application/json | JSON 请求必须设置 |
| Accept | 否 | application/json | 期望返回 JSON |
| Authorization | 否 | 不传 | 当前本地服务不提供 HTTP 鉴权 |

LLM 的 LLM_API_KEY 不放在 HTTP 请求中。扰动模拟服务从进程环境读取
.env.local，不会把密钥写入响应或审计。

### 3. 响应格式

当前服务没有统一的 success/code/msg/data 包装层，各接口直接返回自己的 JSON
业务对象。例如正常预配包直接返回：

~~~json
{
  "request_id": "plan-20260929-0001",
  "status": "completed",
  "algorithm": "decision_tree",
  "results": [],
  "metrics": {},
  "audit": {}
}
~~~

错误响应统一至少包含 error：

~~~json
{
  "error": "离线场景不存在",
  "scenario_id": "does-not-exist"
}
~~~

错误响应不会返回 API Key、Authorization、完整请求体或 LLM prompt。

### 4. 时间和坐标

- API 时间字段使用 RFC 3339，例如 2026-09-29T08:20:00+08:00；
- speed_mps 使用米/秒；
- safe_distance_m 使用米；
- position_m、limit_0_m、limit_1_m 沿用 PLAN 坐标刻度；
- 服务内部会把公共 API 的速度和安全距离转换为决策树内部单位。

## 四、接口总览

| 序号 | 接口名称 | 方法 | URL | 用途 |
| --- | --- | --- | --- | --- |
| 1 | 查询场景库摘要 | GET | /api/scenarios/summary | 查询场景总数和分类统计 |
| 2 | 查询场景列表 | GET | /api/scenarios | 获取场景选择器数据，可按分类过滤 |
| 3 | 查询场景详情 | GET | /api/scenarios/{scenario_id} | 获取事件、资源、分配、校验和审计 |
| 4 | 扰动模拟 | POST | /api/simulate | 执行当前受控扰动 Workflow 演示 |
| 5 | 正常预配包 | POST | /api/v1/ladle-preallocation/allocate | 提交炉次计划和资源快照，生成配包结果 |

> 正式业务调用使用第 5 个接口。第 1～4 个接口主要用于离线场景查询、前端展示和扰动联调。

## 五、查询场景库摘要

### 1. 接口说明

查询离线场景库的版本、总场景数、分类数量、扰动分组数量以及已经验证的
LLM 回退场景数量。

### 2. 请求信息

~~~http
GET /api/scenarios/summary
~~~

请求头：无必填请求头。

请求参数：无。

请求体：无。

### 3. curl 示例

~~~bash
curl -i http://127.0.0.1:4173/api/scenarios/summary
~~~

### 4. 响应示例

~~~json
{
  "schema_version": 2,
  "scenario_count": 21,
  "categories": [
    {"category": "decision_tree_control", "count": 1},
    {"category": "llm_fallback_stress", "count": 20}
  ],
  "disturbance_groups": [
    {"disturbance_group": "equipment", "count": 5}
  ],
  "verified_llm_fallback_count": 20
}
~~~

### 5. 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| schema_version | integer | 离线场景库结构版本 |
| scenario_count | integer | 场景总数 |
| categories | array | 按场景分类统计 |
| categories[].category | string | 场景分类 |
| categories[].count | integer | 分类数量 |
| disturbance_groups | array | 按扰动分组统计 |
| disturbance_groups[].disturbance_group | string | 扰动分组 |
| disturbance_groups[].count | integer | 分组数量 |
| verified_llm_fallback_count | integer | 已验证 LLM 回退成功的场景数量 |

## 七、查询场景详情

### 1. 接口说明

查询一个离线场景的完整只读证据。该接口不会重新执行配包算法。

### 2. 请求信息

~~~http
GET /api/scenarios/{scenario_id}
~~~

路径参数：

| 参数名 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| scenario_id | 是 | string | 离线场景唯一编号 |

请求体：无。

### 3. curl 示例

~~~bash
curl -i http://127.0.0.1:4173/api/scenarios/decision_tree_control_001
~~~

### 4. 响应结构

~~~json
{
  "scenario_id": "decision_tree_control_001",
  "category": "decision_tree_control",
  "disturbance_kind": "crane_offline",
  "events": [],
  "assets": [],
  "responses": {
    "decision_tree": {
      "path": "decision_tree_success",
      "success": true,
      "num_assigned": 1,
      "assignments": []
    }
  },
  "validations": {
    "decision_tree": []
  },
  "audit": {}
}
~~~

### 5. 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| scenario_id | string | 场景编号 |
| category | string | 场景分类 |
| disturbance_kind | string | 扰动类型 |
| events | array | 事件时间线 |
| assets | array | 炉次、钢包、行车、路线资产 |
| responses | object | 决策树和 LLM 阶段结果 |
| responses.{stage}.path | string | 阶段路径 |
| responses.{stage}.success | boolean | 阶段是否成功 |
| responses.{stage}.num_assigned | integer | 阶段已分配炉次数 |
| responses.{stage}.assignments | array | 逐炉次分配结果 |
| validations | object | 各阶段逐条校验结果 |
| audit | object | 数据来源和受控注入审计 |

资源不存在时：

~~~json
{"error": "离线场景不存在", "scenario_id": "does-not-exist"}
~~~

## 八、扰动模拟

### 1. 接口说明

执行当前服务开放的受控扰动 Workflow。该接口用于演示和联调，正式生产配包
使用第九章的正常预配包接口。

当前支持的实时场景编号：

~~~text
real_window_1100_1120_codex_stress_001
~~~

### 2. 请求信息

~~~http
POST /api/simulate
~~~

请求体字段：

| 参数名 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| scenario_id | 否 | string | 受控场景编号；省略时使用默认场景 |

### 3. curl 示例

~~~bash
curl -i -X POST http://127.0.0.1:4173/api/simulate \
  -H 'Content-Type: application/json' \
  -d '{"scenario_id":"real_window_1100_1120_codex_stress_001"}'
~~~

### 4. 成功响应示例

~~~json
{
  "path": "llm_react_success",
  "success": true,
  "num_assigned": 31,
  "num_total": 31,
  "elapsed_seconds": 23.0,
  "remaining_budget_seconds": 194.0,
  "reason": "LLM Workflow 完成并通过硬约束终检",
  "human_review_required": false,
  "api_configured": true,
  "validation_feedback": {},
  "affected_heat_ids": [],
  "workflow": {
    "stage": "completed",
    "configuration_source": "env_local",
    "budget_status": "available",
    "failure_reasons": [],
    "transitions": ["snapshot", "scope", "context", "llm_propose", "validate", "completed"]
  },
  "configuration_source": "env_local",
  "llm_attempted": true,
  "llm_path": "llm_react_success",
  "scenario_id": "real_window_1100_1120_codex_stress_001"
~~~

### 5. 未配置 LLM 响应

没有配置 LLM_API_KEY 时，接口不会伪造成功结果，通常返回 503：

~~~json
{
  "path": "frozen",
  "success": false,
  "human_review_required": true,
  "api_configured": false,
  "llm_attempted": true,
  "llm_path": "llm_react_failure",
  "error": "LLM_API_KEY 未配置；实时请求未伪造成功结果，已返回 Frozen + 人工路径"
}
~~~

### 6. 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| path | string | 决策树、LLM、Frozen 或人工路径 |
| success | boolean | 本次扰动响应是否成功 |
| num_assigned | integer | 已完成分配炉次数 |
| num_total | integer | 受影响炉次数 |
| elapsed_seconds | number | 执行耗时 |
| remaining_budget_seconds | number/null | 剩余安全时间预算 |
| reason | string | 当前路径说明 |
| human_review_required | boolean | 是否需要人工复核 |
| api_configured | boolean | 是否配置 LLM |
| validation_feedback | object | 硬约束校验反馈 |
| affected_heat_ids | array | 受影响炉次编号 |
| workflow | object/null | Workflow 阶段和转移记录 |
| configuration_source | string | LLM 配置来源 |
| llm_attempted | boolean | 是否尝试 LLM |
| llm_path | string/null | LLM 路径结果 |
| scenario_id | string | 场景编号 |

## 十、状态码说明

| HTTP 状态码 | 含义 | 典型场景 |
| --- | --- | --- |
| 200 | 请求处理成功 | 查询成功、完整配包成功、扰动 Workflow 成功 |
| 202 | 任务已创建 | 生产扰动已接收，Workflow 尚未完成 |
| 400 | 请求格式错误 | JSON 错误、缺少字段、时间格式错误、分类参数错误 |
| 404 | 资源不存在 | 查询不存在的场景 |
| 409 | 资源快照冲突 | 重复炉次、重复钢包、重复行车、位置映射冲突 |
| 422 | 业务不可行 | 请求正确但无法完成全部炉次分配 |
| 423 | 结果被冻结 | 需要人工复核、候选未确认或结果不可发布 |
| 500 | 服务内部错误 | 场景库或 Workflow 处理异常 |
| 503 | 本地依赖不可用 | 场景库不存在、扰动模拟未配置 LLM |

## 十一、生产扰动重调度接口

### 1. 设计边界

正常预配包接口生成一个不可变基线。真实扰动引用这个基线，并生成新的局部重调度 revision：

```text
正常预配包 -> allocation_version
扰动事件 -> job_id -> revision_id -> 人工确认 -> 发布
```

`/api/simulate` 仍是固定场景演示接口，不接收生产现场的实际快照。生产调用必须使用下面的版本化接口。

### 2. 版本字段

| 字段 | 产生阶段 | 说明 |
| --- | --- | --- |
| `plan_version` | 上游计划/正常预配 | 炉次计划版本，服务不修改其内容 |
| `snapshot_version` | 资源快照 | 钢包、行车、位置和工艺状态快照版本 |
| `allocation_version` | 正常预配 | 决策树配包结果版本 |
| `disturbance_id` | 扰动上报 | 一次现场扰动的幂等编号 |
| `job_id` | 扰动接收 | 一次重调度 Workflow 任务编号 |
| `revision_id` | Workflow 结果 | 基于父版本产生的候选或已发布结果 |
| `parent_revision_id` | Workflow 结果 | 该 revision 依赖的配包版本或上一版 revision |

### 3. 接收生产扰动

```http
POST /api/v1/ladle-preallocation/disturbances
```

请求头可选：

```text
Idempotency-Key: DIST-20260929-0007
```

请求示例：

```json
{
  "disturbance_id": "DIST-20260929-0007",
  "event_type": "crane_offline",
  "occurred_at": "2026-09-29T08:40:00+08:00",
  "resource_id": "2500",
  "plan_version": "PLAN-20260929-V3",
  "allocation_version": "ALLOC-20260929-0001",
  "snapshot_version": "SNAPSHOT-20260929-083500",
  "affected_heat_ids": ["AQ0640E1", "AQ0641E1"],
  "locked_heat_ids": [],
  "current_snapshot": {
    "heats": [],
    "ladles": [],
    "cranes": [],
    "location_map": []
  }
}
```

核心输入字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `disturbance_id` | 是 | 一次扰动的唯一编号，重复提交不会重复调用 LLM |
| `event_type` | 是 | 行车、钢包、设施、计划节拍或复合扰动类型 |
| `occurred_at` | 是 | 扰动发生时间，RFC 3339 |
| `resource_id` | 条件必填 | 受影响行车、钢包或设施编号 |
| `plan_version` | 是 | 所依据的上游炉次计划版本 |
| `allocation_version` | 是 | 所依据的正常配包结果版本 |
| `snapshot_version` | 是 | 所依据的资源快照版本 |
| `affected_heat_ids` | 否 | 上游已明确的影响炉次；未传时由服务计算 |
| `locked_heat_ids` | 否 | 已开始执行、禁止改配的炉次 |
| `current_snapshot` | 否 | 最新炉次、钢包、行车和位置快照；不传则使用基线快照 |

支持的 `event_type` 包括：

```text
crane_offline
crane_speed_degraded
crane_load_restricted
crane_range_restricted
ladle_unavailable
ladle_damage
ladle_lining_alarm
ladle_over_age
facility_unavailable
argon_station_unavailable
refining_route_change
schedule_deviation
converter_delay
caster_delay
urgent_heat_inserted
priority_escalation
crane_telemetry_stale
compound_disturbance
```

curl 示例：

```bash
curl -i -X POST http://127.0.0.1:4173/api/v1/ladle-preallocation/disturbances \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: DIST-20260929-0007' \
  -d '{
    "disturbance_id": "DIST-20260929-0007",
    "event_type": "crane_offline",
    "occurred_at": "2026-09-29T08:40:00+08:00",
    "resource_id": "2500",
    "plan_version": "PLAN-20260929-V3",
    "allocation_version": "ALLOC-20260929-0001",
    "snapshot_version": "SNAPSHOT-20260929-083500",
    "locked_heat_ids": [],
    "current_snapshot": {"heats": [], "ladles": [], "cranes": [], "location_map": []}
  }'
```

### 4. 查询任务和 revision

```http
GET /api/v1/ladle-preallocation/jobs/{job_id}
GET /api/v1/ladle-preallocation/revisions/{revision_id}
```

任务状态包括：

```text
received -> scoped -> running -> pending_confirmation -> confirmed -> published
                                  \-> frozen / human_review
```

成功候选响应示例：

```json
{
  "job_id": "JOB-20260929-0009",

  "status": "pending_confirmation",

  "versions": {
    "plan_version": "PLAN-20260929-V3",
    "allocation_version": "ALLOC-20260929-0001",
    "snapshot_version": "SNAPSHOT-20260929-083500"
  },
```

### 5. 人工确认和发布

候选结果不能直接下发。必须先确认，再发布：

```http
POST /api/v1/ladle-preallocation/revisions/{revision_id}/confirm
POST /api/v1/ladle-preallocation/revisions/{revision_id}/publish
```

请求体：

```json
{
  "operator": "dispatcher-01",
  "reason": "人工确认方案可执行"
}
```

发布接口会重新检查父版本、资源快照、硬约束结果和确认状态。Frozen、人工复核、驳回、过期或未确认的 revision 不允许发布。
