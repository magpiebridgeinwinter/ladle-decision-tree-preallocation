## 目标

把当前凌乱、文字过多的页面重做成一个可以给管理者、调度人员和项目评审现场演示的交互式生产事故推演界面。

观众必须在十秒内看懂三件事：

1. 大模型只在决策树局部重排失败后介入，不是替代整个调度系统。
2. 真实实验中决策树未完成局部窗口，Codex 方案完成对应窗口并经过统一硬约束终检；主场景数字为 `30/31 -> 31/31`，双炉场景为 `0/2` 或 `1/2 -> 2/2`。
3. 相比“决策树失败后直接等待人工”，LLM 能在九十秒人工升级点前给出可审计候选方案，但不能绕过安全校验。

## 信息架构

页面只保留两个一级模式，使用明显的分段控制器切换：

- `普通局部重排`：决策树完成当前窗口全部炉次，不调用 LLM。
- `LLM 严重扰动`：默认模式，突出 20 类压力场景。

不要再使用 Frozen、决策树、LLM、人工四列并排的旧布局。

建议页面结构：

1. 顶部紧凑控制栏：模式切换、事故选择、播放控制、当前生产时刻。
2. 主体左侧：钢包、行车、工位和运输路径构成的生产现场动画。
3. 主体右侧：四阶段响应链和三个核心结果数字。
4. 页面底部：可折叠的真实数据、逐炉方案、约束验证和审计证据。

不要嵌套卡片，不要用大段解释文字铺满首屏，不要同时展示 20 个事故卡片。事故选择器按分组下拉或搜索。

## 全局时间条

必须增加 `10:00-20:00` 全局生产时间条，并实现：

- 自动播放；
- 暂停；
- 上一步、下一步；
- 复位；
- 拖动时间；
- 切换事故后自动复位；
- 动画能够继续推进到恢复生产和 `20:00`，不能停在 LLM 决策阶段。

详情接口中的 `events` 是动画状态机的唯一数据源，不要在多个组件里重复硬编码阶段。

严重扰动的阶段顺序：

`预配完成 -> 扰动发生 -> 打开二十分钟局部窗口 -> 决策树失败 -> 组装局部上下文 -> Codex 方案 -> 硬约束终检 -> 调度下发 -> 恢复生产`

普通扰动中，决策树成功后直接下发，不出现伪造的 LLM 阶段。

## 事故动画

使用接口中的 `visual_cue` 决定动画，不能所有事故都显示火焰。

- 行车离线：断电、停止移动、轨道状态转为不可用。
- 行车降速：明显减速并显示速度报警。
- 行车限载：吊重或载荷表报警。
- 行车范围受限：轨道出现禁行边界。
- 通道封锁：运输路径出现安全隔离带。
- 钢包不可用：进入维护隔离区。
- 钢包损坏：包体裂纹和红色隔离标识。
- 内衬报警：钢包内部高温或耐材报警。
- 钢包超龄：时钟和超时状态。
- 等级冲突：钢种/钢包等级不匹配提示。
- 设施或氩站停机：对应工位熄灭并禁止进入。
- 路线变化：旧路径关闭，新路线逐段亮起。
- 转炉或连铸延迟：对应工位时间状态滞后。
- 紧急炉次插入、优先级提升：炉次进入局部窗口并升到队列前部。
- 遥测陈旧：信号断续、时间戳过期。
- 复合扰动：组合显示行车、钢包和路线三类状态。

动画必须与受影响的真实资源同步，不得只是装饰。

## LLM 作用展示

严重扰动的视觉主线固定为：

`决策树未完成当前窗口 -> Codex 生成完整局部组合 -> 统一终检 -> 当前窗口全部完成后下发`

主结果区只放三个醒目数字：

- 决策树完成数；
- Codex 完成数；
- 通过的硬约束检查数。

点击阶段后用抽屉或展开区展示细节：

- 决策树失败原因来自 `responses.decision_tree.assignments`；
- Codex 具体方案来自 `responses.llm.assignments`；
- 校验结果来自 `validations.llm`；
- 事故前后变化来自 `audit.controlled_overrides.event_state_deltas`；
- 真实字段来自 `assets[].source_record`。

不得写“AI 自动接管生产”。正确说法是：

“Codex 生成候选重排方案，经统一硬约束终检后下发。”

## 视觉要求

这是宝钢生产调度演示，不是营销落地页。整体应安静、专业、工业化、适合长时间查看：

- 高信息密度但层级清楚；
- 用有限的警报红、设备黄、通过绿表达状态；
- 不使用大面积紫色渐变、装饰光球、浮夸英雄区；
- 页面分区尽量无框，卡片只用于重复场景项或详情抽屉；
- 按钮优先使用项目现有图标库或 Lucide 图标，并提供 tooltip；
- 控件尺寸稳定，播放时不能跳动；
- 桌面和移动端文字、按钮、时间条及动画不得重叠或溢出；
- 首屏避免说明书式文案，让数据、动画和状态自己解释流程。

可以使用 DewuClaw 中适合数据可视化、工业控制界面、时间线动画和响应式布局的 skills，但必须服从项目已有技术栈，不要无必要更换框架或引入大型依赖。

## 证据边界

页面必须保留可点击的“数据与实验说明”，准确说明：

- 炉次、钢包、行车、路线和快照来自 `PLAN(1)`、`CRANE` 真实数据审计；
- 20 类事故是基于真实资产构造的可复现压力输入，不是宝钢历史事故日志；
- 离线 Codex 方案是已保存、已审计的方案，`external_api_called=false`；
- 当前结果验证的是调度输入契约和硬约束闭环，不等于现场 PLC、安全联锁、全局行车碰撞或生产投运验收。

不要出现 H-FLEX、H-TIGHT、C0 等虚构标签。
