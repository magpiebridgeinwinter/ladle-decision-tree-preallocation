# LLM 局部重调度方案 PRD

> Product Requirements Document — 钢包智能排程系统 · 扰动局部重调度  
> 2026-08-06 · grill-me 二轮盘问结论 · 6/6 问题全部闭合 · 阈值 90s · 可进入开发

---

## 1. 背景与目标

### 当前状态

| 项目 | 现状 |
|------|------|
| 预配包 | 规则决策树，416 条炉次（PLAN）+ 行车快照（CRANE），成功率 100% |
| 工业场景 | 湛江钢铁炼钢厂，43 钢包（22 在线）+ 7 行车，24h 连续生产 |
| 异常处理 | 设备异常 → 调度员暂停 → 评估 → 录入 → "重启排程" → 模型重算 |

### 目标

用 **LLM 替代人工调度员**，在生产出现扰动时自动完成局部重调度。LLM 的角色不是替代决策树，而是**在决策树搞不定的困难场景中顶上**，避免退回人工。

---

## 2. 核心方案

### 整体架构

```
预配包（决策树）→ 滑窗渐进式执行 → 执行中发生扰动 → 分级响应
```

### 分级响应流程

#### ⚡ 紧急（最早开浇 ≤ 90s）

```
决策树毫秒级重排 ──成功──→ 下发指令
  │
  └──失败──→ Frozen（硬扛）+ call 人工
```

> ※ 紧急场景不上 LLM，LLM 推理延迟不可控，直接呼叫人工

#### 🧠 非紧急（最早开浇 > 90s）

```
决策树快速重排 ──成功──→ 下发指令
  │
  └──失败──→ LLM ReAct 重调度 ──成功──→ 下发指令
                │
                └──失败──→ Frozen（硬扛）→ 告警等人工
```

> ※ 流程顺序：决策树先行（毫秒级），失败才上 LLM——LLM 只处理决策树搞不定的困难场景  
> ※ 安全阈值 90s：最早开浇前 90 秒为硬截止，超时不再计算，直接 Frozen

### 预配包模式：滑窗渐进式

| 要素 | 说明 |
|------|------|
| 输入 | 416 条炉次（2026-03-06 全天，14-24 炉次/小时） |
| 触发 | 转炉开吹前 180 分钟，逐批触发预配 |
| 状态池 | 已吹炼（锁定）/ 已预配未吹炼（可扰动波及）/ 未预配 |
| 改造 | 全量回放 → 滑窗（pipeline.py 改造） |

### LLM ReAct 重调度

| 参数 | 值 |
|------|-----|
| 触发条件 | 决策树局部重排失败 |
| LLM 选型 | 初步采用 deepseek-v4-flash（成本优先），后续可根据效果切换 |
| 轮数策略 | 不做硬上限，按剩余时间预算动态分配（最早开浇 - 90s 安全阈值） |
| 单轮超时 | 由预算 / 预期轮数动态切分 |
| 角色定位 | 模仿人工调度员——可输出意图级指令让引擎落地，也可直接出钢包/行车映射 |
| 输入 | 受影响炉次 + 可用钢包 + 可用行车 + 硬约束规则 + 决策树失败原因 |
| 输出 | `{heat_id → ladle_id + crane_id}` 映射，或意图级指令（如"X 号炉次优先级最高，优先保障"） |
| 反馈 | 逐条违反详情（炉次/钢包/约束/可替代资源） |
| 后续扩展 | 建立调度员 RAG（待企业提供调度经验知识），注入领域知识 |

#### ReAct 循环（动态轮数）

```
轮 N（LLM 出方案）→ 校验器（返回违反详情）→ 轮 N+1（LLM 修正）→ 校验通过 → 下发指令
                                                              │
                                                        预算耗尽 → Frozen
```

> ※ 校验通过 → 提前退出。预算耗尽（距最早开浇不足安全阈值）→ 不再继续，Frozen + 告警。

## 3. 量化评估框架

### 扰动类型

| 类型 | 触发条件 |
|------|---------|
| 行车不可用 | online_status=0 或被锁定维修 |
| 钢包状态异常 | offline / maintenance / scrapped，或氩气故障 |
| 设施不可用 | 修包工位、烘烤位不可用 |
| 计划偏差 | 实际时间与计划偏差 ≥ 300s |

> ※ Demo 阶段：单类型扰动，随机时间点注入，不模拟组合扰动。后续迭代再逐步增加复杂度。

### 三路对比

| 路径 | 含义 | 角色 |
|------|------|------|
| ❄️ Frozen | 原预配包不动，扰动硬扛 | 底线参照 |
| 📐 Deterministic | 决策树局部重排（score 取最优） | 自动化基线 |
| 🧠 LLM | LLM ReAct 重调度（仅决策树失败后触发） | 评估目标 |

### 对比指标

| 指标 | 含义 |
|------|------|
| on_time_rate | 按时配包率 |
| priority_on_time | 优先级加权按时配包数 |
| average_delay_seconds | 平均延迟 |
| max_delay_seconds | 最大延迟 |
| changed_heats | 变更炉次数（越少越稳定） |
| human_review_rate | 人工审核触发率（越低越省人力） |
| rule_violations | 规则违反次数 |
| decision_seconds | 决策耗时 |
| dtree_fail_llm_success_rate | **新增**：决策树失败后 LLM 的成功率（核心价值指标） |
| frozen_avoidance_rate | **新增**：LLM 避免退到 Frozen 的比例 |

## 4. 问题讨论结论

| 问题 | 状态 | 结论 |
|------|------|------|
| **Q1** LLM 胜负判定标准 | ✅ 已闭合 | LLM 是决策树的兜底补充而非竞争对手。核心指标为 dtree_fail_llm_success_rate 和 frozen_avoidance_rate。后续迭代可加入二者对比，但当前不设单一胜负标准。 |
| **Q2** 扰动类型和频率 | ✅ 已闭合 | 无真实异常日志，采用人工注入方式。Demo 阶段注入单类型扰动，模拟现场最常见的高频场景（行车故障、钢包异常）。 |
| **Q3** 扰动注入时间点 | ✅ 已闭合 | Demo 阶段：随机时间点 + 单扰动。先跑通完整链路，后续迭代再加入时段分区和组合扰动。 |
| **Q4** 对比基线 | ✅ 已闭合 | 决策树重排当基线合理。LLM 的价值在于"决策树解不出来的 case 上 LLM 能顶上"。新增 dtree_fail_llm_success_rate 为核心指标。 |
| **Q5** LLM 输出方式 | ✅ 已闭合 | 不做死限制。LLM 充当人工调度员角色：可输出意图级指令让引擎落地，也可直接出钢包/行车映射。后续计划建立调度员 RAG 注入领域知识。 |
| **Q6** LLM 角色边界与流程顺序 | ✅ 已闭合 | 流程顺序：先决策树 → 失败才上 LLM。安全阈值 90s：≤90s 为紧急（决策树失败直 call 人工），>90s 为非紧急（决策树失败后上 LLM）。LLM 轮数不做硬上限，预算 = 最早开浇 - 90s。 |

## 6. Demo 执行流程

```
Step 1: 构建全量 baseline
  PLAN(20 炉次) + CRANE → build_real_data_scenario
  → heuristic.allocate → 20 条分配结果（baseline）

Step 2: 注入扰动
  inject_disturbance(snapshot, seed=42)
  → 把某一行车标记为 offline

Step 3: 检测扰动 + 计算影响范围
  detect_disturbances(baseline, snapshot)
  → 输出: ["crane_unavailable: crane_3"]
  impact_scope(baseline, heats, events)
  → 输出: impacted_heats = [heat_5, heat_8, heat_12]

Step 4: 分级响应
  找 impacted_heats 中最早开浇时间 → earliest_pour
  计算 budget = earliest_pour - now - 90s

  if budget ≤ 0:   → 🔴 紧急分支
    决策树重排 → 成功? → 下发
              → 失败? → Frozen + call 人工

  if budget > 0:    → 🟢 非紧急分支
    决策树重排 → 成功? → 下发
              → 失败? → 进 Step 5

Step 5: LLM ReAct（仅在决策树失败时触发）
  Prompt = {受影响炉次, 可用钢包, 可用行车, 硬约束规则, 决策树失败原因}
  → DeepSeek-v4-flash 生成分配方案
  → 校验器逐条检查 → 返回违反详情
  → 通过 → 下发 / 未通过 + 预算未耗尽 → 反馈修正循环
  → 预算耗尽 → Frozen + 告警

Step 6: 三路对比报告
  Frozen（baseline 硬扛）、决策树重排、LLM 重排
  → 指标统计汇总
```
