# LLM 局部重调度方案验证报告

**日期：** 2026-08-25  
**分支：** `feature-1.0`  
**数据范围：** 真实 `PLAN(1).xlsx`、`CRANE.xlsx`；全量 457 炉基线与 11:00–11:20 局部窗口压力回放。

## 1. 背景与目标

预配包在生产启动前由决策树完成。生产运行中若发生行车、钢包、工艺设施、计划节奏或数据状态扰动，系统只重排“当前时刻附近、尚未锁定”的局部窗口，不影响已经完成生产的炉次，也不提前改动远期炉次。

本次实现的目标是验证：当决策树无法完成局部窗口时，Codex 是否能够读取真实炉次、钢包、行车和路线约束，给出完整可执行的替代方案，并通过统一校验后下发。

## 2. 核心方案

预配包（决策树） -> 生产滑窗推进 -> 11:00 发生受控扰动 -> 打开 11:00–11:20 的 31 炉局部窗口 -> 决策树先行 -> 失败后 Codex 介入 -> 完整性、硬约束、场景策略校验 -> 下发。

本次场景在最早开浇前保留 313.1 s，扣除 90 s 安全阈值后仍有 223.1 s，属于允许 Codex 介入的非紧急路径。紧急路径仍应在 90 s 阈值内停止模型计算并冻结方案、请求人工复核。

## 4. 实验结果

### 4.1 决策树失败

在 31 炉局部窗口中，决策树完成 30/31。首炉 `JU6310E7-300751` 因场景约束终检发现 `missing_refining_route` 未分配，导致该路径不完整，不能直接下发。

### 4.2 Codex 介入

Codex 读取 31 炉窗口、可用行车集合和场景约束，采用“尽量保持原计划、只替换不可用行车”的局部策略：27 炉保持原计划，4 炉完成行车替换。钢包均保持 `ST51 -> ST51`，本次变化集中在行车资源。

| 炉次 | 原钢包 | 原行车 | 新钢包 | 新行车 |
| --- | --- | ---: | --- | ---: |
| JU6310E7-300755 | ST51 | 2500 | ST51 | 2170 |
| JU6310E7-300762 | ST51 | 2500 | ST51 | 2170 |
| AP0961E3-300774 | ST51 | 2500 | ST51 | 1170 |
| AR4143E5-300781 | ST51 | 2500 | ST51 | 1170 |

Codex 结果为 31/31，按时率 100%，平均延迟 0 s，规则违反 0。完整分配、共享硬约束、场景策略三类校验全部通过。

### 4.3 三路对比

| 指标 | Frozen 不重排 | 决策树重排 | Codex 局部重排 |
| --- | ---: | ---: | ---: |
| 完成分配 | 0/31 | 30/31 | 31/31 |
| 按时率 | 0.00% | 96.77% | 100.00% |

Frozen 仅作为“不采取局部重排”的对照，不等同于现场人工方案。Codex 结果是离线审计中的 Codex-authored proposal，本次没有访问外部 LLM API；线上部署仍需保留 API Key 配置、超时、审计和人工审批链路。

离线 SQLite 场景库共 21 条：1 条决策树成功对照场景，20 条决策树失败后 Codex 成功的压力场景。覆盖行车、运输通道、钢包、工艺设施、计划节奏、数据状态和复合扰动：

| 场景组 | 覆盖内容 | 场景数 |

上述场景使用真实 PLAN/CRANE 快照作为输入，但扰动事件和压力参数由场景构造器注入，不能解释为生产事故统计。

## 6. 结论与边界

本次验证完成了“决策树优先 -> 失败识别 -> Codex 局部重排 -> 统一校验 -> 方案下发”的离线闭环。真实 11:00–11:20 窗口中，Codex 将决策树的 30/31 提升为 31/31，只改动 4 炉，且 27 炉保持原计划，体现了局部重排而非全量重算。

当前结果证明的是离线回放和可复现压力场景下的方案生成与审计能力，不替代现场实时生产验收、安全联锁、人工审批或真实 API 延迟评估。下一步应接入实时事件流，补充现场约束字段，设置 90 s 超时冻结策略，并在沙箱环境开展人工确认式联调。
