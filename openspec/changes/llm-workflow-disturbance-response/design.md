## Context

当前系统有两条逻辑：`real_data.pipeline` 从 PLAN、CRANE 和位置映射生成决策树预配包；`TieredResponseController` 在扰动后再次先运行决策树，只有失败且仍有时间预算时才调用 LLM。新的产品边界要求把上游炉次计划明确为输入，保留决策树用于正常预配包，并把扰动生产路径改成直接进入 LLM Workflow。

约束仍然由代码负责：锁定炉次不能被改写，LLM 只能使用场景提供的资源，候选结果必须经过现有硬约束验证和影响范围保护。LLM 配置来自 CLI 参数或进程环境变量；本变更不引入自动读取 `.env.local` 的隐式行为。

## Goals / Non-Goals

**Goals:**

- 把正常预配包和扰动重调度拆成两个明确阶段。
- 让每个可重调度扰动进入一个可审计的 Workflow 状态机，生产路径不再先调用决策树局部重排。
- 保留 ReAct 的多轮提案、约束反馈、时间预算和最终校验。
- 在 LLM 未配置、调用失败、预算耗尽或方案非法时稳定降级到 Frozen/人工复核。
- 保留决策树重排作为离线基线和三路评估能力。

**Non-Goals:**

- 不让 LLM 生成或修改上游炉次计划。
- 不删除决策树预配包、共享校验器、扰动注入器或离线评估代码。
- 不把未经校验的 LLM 输出直接下发到生产控制系统。
- 不引入 LangGraph、Temporal 或其他新的工作流运行时依赖。

## Decisions

### 1. 用显式 Python Workflow 编排，不引入工作流框架

Workflow 由确定性的阶段函数和状态对象组成：`snapshot`、`scope`、`context`、`llm_propose`、`validate`、`dispatch_or_review`。这样沿用现有测试、审计和部署方式，也避免把领域约束藏入第三方框架。未来若需要跨进程持久化，再把同一状态契约映射到外部编排器。

### 2. 扰动生产路径直接进入 LLM 阶段

`handle_disturbance` 不再调用 `_run_decision_tree` 作为生产前置步骤。它使用扰动注入器已经生成的局部炉次、可用钢包、可用行车、锁定集合和事件差异构造 LLM 上下文，然后调用 ReAct。`run_three_way` 和批量基准仍可显式运行决策树，以保留历史结果可比性。

### 3. 紧急预算是安全门，不是第二种调度算法

每个扰动都先创建 Workflow 状态。若剩余预算大于零，调用 LLM；若预算耗尽、LLM 未配置或调用超时，Workflow 记录跳过/失败原因并返回 Frozen + 人工复核。系统不会为了满足“进入 LLM”而在零预算下阻塞生产或绕过人工升级。

### 4. 保留现有校验器作为唯一接受门

LLM 结果必须满足完整炉次覆盖、唯一钢包、有效行车、载重、位置区间、时间窗、安全距离、钢包状态、路线和锁定炉次保护。Workflow 只接受通过校验且未修改影响范围外炉次的结果。

### 5. 配置采用显式来源

`ReActRescheduler` 接受显式的 `api_key`、`api_base` 和 `model`。CLI 继续使用 `--llm-*` 参数；HTTP 服务继续读取 `LLM_API_KEY`、`LLM_API_BASE`、`LLM_MODEL`。审计只保存 `configured`、来源名称和模型/地址，不保存密钥或完整 prompt。

## Risks / Trade-offs

- [Risk] 直接 LLM 路径的延迟高于决策树 → 以剩余预算限制每轮调用，超时立即进入人工降级；正常预配包仍保持决策树速度。
- [Risk] LLM 可能输出部分或重复炉次 → 复用完整覆盖检查和硬约束验证，非法方案永不成为有效结果。
- [Risk] 历史三路报告仍表达“决策树失败后 LLM” → 区分生产 Workflow 结果与离线基准字段，更新报告和测试文案。
- [Risk] 环境变量配置与 CLI 配置来源不同 → 统一在运行入口构造配置对象，并在审计中记录非敏感来源。

## Migration Plan

1. 增加 Workflow 状态和生产路径分支，先保留旧决策树方法供离线基准调用。
2. 更新 ReAct prompt、控制器输出、实时 API 和离线场景审计字段。
3. 增加直接 LLM 路径、预算降级、非法提案和配置来源测试。
4. 运行完整测试和 OpenSpec 校验；如需回滚，将生产入口切回旧控制器方法，离线数据格式保持向后兼容。

## Open Questions

- 现场最终下发接口尚未接入，本变更只定义“可执行候选方案”输出，不定义 PLC/调度系统写入协议。
- 是否在后续版本允许 LLM 输出“意图级指令”而非直接映射，需要等调度员知识库和执行器契约确定后再扩展。
