## Context

项目已经能够使用 `loc_location.xlsx` 生成位置映射后的决策树预配审计，但现有扰动压力演示仍读取旧的未映射决策树审计。这样会导致同一炉次在“扰动前基线”和“扰动后重排”中使用不同位置输入，无法判断决策树或 LLM 的真实作用。

现有 `DisturbedScenario`、`TieredResponseController`、`ScenarioValidator` 和离线 SQLite/JSON 证据层已经提供大部分响应链路。本变更的重点是更换场景输入基线、扩展位置字段在扰动后的传递，并让所有响应路径遵守同一套局部影响、时间预算和最终校验契约。

## Goals / Non-Goals

**Goals:**

- 从位置映射决策树审计恢复真实 PLAN/CRANE/位置输入和全量基线分配。
- 在同一位置映射上下文中注入所有当前支持的扰动类型和受控演示事件。
- 只对事件影响范围内、尚未锁定的炉次重排；冻结范围内的原分配保持不变。
- 复用现有分级控制器：决策树先行，非紧急且决策树失败时再调用 LLM，最终失败进入 Frozen/人工。
- 让决策树和 LLM 的候选校验使用同一位置、时间窗、钢包、行车和事件特定约束。
- 保存可复现的三路结果、影响范围、位置来源、失败原因、LLM 输入输出摘要和校验结果。
- 保留离线审计夹具和实时 API/LLM 适配器两种入口。

**Non-Goals:**

- 不在本变更中调整位置坐标本身、决策树评分权重或工厂策略拟合规则。
- 不把工厂 `AE` 历史方案直接作为扰动响应答案。
- 不把离线 Codex 夹具描述为真实外部 API 请求。
- 不改变 90 秒安全阈值、180 分钟预配窗口或现有 LLM 密钥传入方式。
- 不接入真实生产控制、自动下发现场指令或替代人工安全审批。

## Decisions

### 1. 位置映射审计是场景唯一基线

新增扰动回放入口接收位置映射决策树审计路径，优先读取其中的 `scheduling_inputs`、`assignments` 和 `location` 元数据。场景构建不得重新从未映射数据推导另一套基线；若审计缺少位置输入或算法标记不匹配，直接失败并提示先运行位置映射预配。

备选方案是让扰动脚本再次从 PLAN/CRANE 读取并自行构造输入。该方案容易产生与 AP 不一致的状态，故不采用。

### 2. 事件只改变局部可变状态

扰动注入保持 `baseline_assignments` 不可变，基于事件产生 `remaining_ladles`、`remaining_cranes`、受影响炉次和重排副本。已吹炼、已执行或显式锁定炉次进入 `excluded_locked_heat_ids`，不参与决策树或 LLM；事件窗口外的炉次保留原方案。

对行车、钢包和设施事件删除/阻断对应资源；对计划偏差调整受影响炉次的时间字段。设施和工艺路线事件必须把路线约束传入最终校验，不能仅通过更换钢包/行车宣称解决。

### 3. 统一的分级响应

控制器对局部可变炉次执行以下顺序：

```text
位置映射基线
    -> 扰动注入与影响范围
    -> 决策树局部重排
       -> 成功：合并冻结结果并下发
       -> 失败且预算 > 0：LLM ReAct
          -> 校验通过：合并并下发
          -> 失败/超时：Frozen + 人工复核
       -> 紧急/预算 <= 0：Frozen + 人工复核
```

预算使用 `最早受影响开浇时刻 - 事件时刻 - 90 秒`。LLM 只能接收决策树失败后的局部上下文和失败反馈，不能绕过决策树或共享校验器。

### 4. LLM 结果必须完整合并并复核

LLM proposal 必须覆盖每个可重排受影响炉次且仅覆盖一次；不得引入未知炉次、钢包或行车。校验器使用与决策树相同的 `validate_output`，并额外执行事件类型对应的路线/设施策略。通过后才与冻结分配合并；合并后再次检查未受影响炉次未被修改。

离线 Codex 方案通过一个与实时 LLM 相同签名的 adapter 注入控制器，并记录 `external_api_called=false`。实时 adapter 仍从运行时 API key 获取凭据，凭据不得进入审计、报告或 SQLite。

### 5. 审计和离线场景输出

每个场景记录位置基线来源、事件状态差异、影响炉次、锁定排除炉次、预算、决策树结果、LLM 结果、Frozen 结果、改配炉次和逐条验证。离线场景数据库沿用现有两类分类：普通决策树控制和 LLM 兜底压力场景；压力场景必须证明决策树不完整、LLM 被调用且完整通过校验。

### 6. 向后兼容

现有未传入位置映射的单元测试 fixture 保持可运行；新增位置感知扰动入口必须显式传入位置映射审计。旧的四类扰动 API 签名不删除，新增字段使用可选参数或审计字段承载。

## Risks / Trade-offs

- [Risk] 位置映射后的资源距离改变，旧的压力场景可能不再触发决策树失败 → [Mitigation] 受控压力输入只注入资源状态/路线策略，不修改真实位置；构建器每次验证 DT 不完整后才允许保存压力场景。
- [Risk] 局部范围过大导致重排波及已执行或远期炉次 → [Mitigation] 由生命周期锁定集合和事件窗口共同裁剪，并保存影响集合与排除集合。
- [Risk] LLM 返回完整但改变非受影响炉次 → [Mitigation] 合并前做最小变更检查，失败则 Frozen。
- [Risk] 位置审计与场景文件来源不一致 → [Mitigation] 审计写入 source audit、位置文件路径和算法版本，并在构建初期校验。
- [Risk] 离线夹具掩盖实时 LLM 延迟或服务错误 → [Mitigation] 审计明确离线模式；实时链路保留 timeout、transport error 和预算失败测试。

## Migration Plan

1. 扩展场景构建和压力场景构建器，要求并验证位置映射预配审计。
2. 将现有通用扰动和受控 Codex 压力演示切换到位置感知审计输入。
3. 运行所有扰动类型，分别保存普通决策树控制和 LLM 兜底压力结果。
4. 重建 SQLite/JSON 离线证据并运行 API、响应控制器和完整性验证。
5. 若发现问题，回滚到旧构建命令和旧审计目录；位置映射预配输出本身不受影响。
