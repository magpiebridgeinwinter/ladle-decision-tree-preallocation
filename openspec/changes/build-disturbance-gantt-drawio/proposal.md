## Why

当前 Excel 和网页能够展示扰动后的分配结果，但观阅者无法沿时间轴看清事故发生、哪些炉次被波及、这些炉次在两条重排线路中分别被分配到哪个钢包和哪台天车。需要用可编辑的 draw.io 图把“预配包”和“扰动后局部重排”串成一条可审计的时间线。

## What Changes

- 新增基于真实离线场景审计的甘特图数据生成能力，统一读取基线分配、事故时间、受影响炉次、决策树结果和 Codex 结果。
- 输出一个 `.drawio` 源文件，包含“行车离线前受影响炉次原计划”和“行车离线后受影响炉次重排结果”两页。
- 两页只逐行展示 31 个受影响炉次，其余 426 炉压缩成上下文说明，避免全量计划淹没扰动重点。
- 横轴裁剪到事故前一小时至全部受影响炉次结束后的整点，并标出扰动时刻和局部影响窗口。
- 在两页甘特图中逐炉显示计划起止时间和钢包/天车分配；离线后变更炉次必须有显著但有限的视觉标记。
- 在图例和节点文案中明确：`炉次 -> 钢包` 是预配包，`钢包转运任务 -> 天车` 是运输调度；没有取包点、落包点和实测轨迹时，不将图称为真实天车运动轨迹。
- 生成可追溯的图形数据 JSON/CSV，使每个图形元素能够回溯到场景 ID、炉次号和审计字段。
- 使用 `diagram-design` 的 Gantt 规范：时间轴横向、正交连线、有限强调色、底部图例和复杂度拆分；用其 draw.io 导入校验脚本验证源文件可打开。

## Capabilities

### New Capabilities

- `disturbance-gantt-drawio`: 从离线扰动审计生成可编辑、可追溯的生产甘特图和炉次重排流程图。

### Modified Capabilities

- 无

## Impact

- 影响 `outputs/real_data_codex_stress_demo/audit.json`、`outputs/offline_scenarios/` 等离线场景数据的读取和转换。
- 新增图形数据生成工具及 draw.io 导出产物，不修改原始 `PLAN(1)`、`CRANE` 和位置映射数据。
- 可能复用前端已有场景目录，但本变更的核心交付是独立的 `.drawio` 源文件和配套数据文件。
- 需要增加真实场景回归测试、draw.io 导入验证和关键炉次/事故标记完整性检查。
