## Context

本项目已有真实数据回放和离线审计结果：AP 是位置映射后的共同基线，AQ 是决策树局部重排，AR 是当前 Codex 独立重排。现有汇报图把流程、事故和结果挤在一张图中，出现文字重叠；报告正文偏长，也没有先说明两条方案如何公平比较和如何选择。

本变更只调整汇报表达层和评价契约，不改变调度求解、Excel、SQLite 或原始数据。目标受众是管理者、调度人员和项目评审，首屏必须先看到 AQ/AR 的真实结果，再理解选择逻辑。

## Goals / Non-Goals

**Goals:**

- 用一张双线路主图说明 `AP → AQ` 与 `AP → AR` 使用相同输入、独立求解、共同终检。
- 用一张评价指标体系图说明从可行性到效果再到稳定性的评判顺序。
- 用 1.5 倍行距和短句重写报告，突出真实结果与方案选择。
- 对本次真实窗口给出可复核的推荐：AQ `30/31`，AR `31/31`，AR 改配 3 炉、28 炉保留 AP，规则违反 0。

**Non-Goals:**

- 不把 Frozen、人工或 20 类事故作为主对比方案。
- 不改变 AQ、AR 的分配结果，不使用 AQ 作为 Codex 的输入。
- 不配置外部 LLM API，不把离线 Codex 方案伪装成线上调用。
- 不以单一“改动少”指标覆盖硬约束失败或按时性失败。

## Decisions

### 1. 主图采用双线路流程图

主图使用 `slide-16x9`、`balanced`、`executive` 规格，节点控制在 7 个以内。顶部展示共同输入和事件窗口，中部左右或上下分流展示 AQ 与 AR，底部汇合到“统一终检”和“选择结果”。所有连接线使用正交路径，箭头标签放在空白处，标签不压线、不压节点。

选择流程图而不是泳道图，是因为本次重点是两个求解方案的独立性和比较关系，不是展示多个组织角色的责任交接。事故细节只保留行车 2500 离线这一真实回放输入，避免主图被场景分类淹没。

### 2. 评价指标图采用门槛 → 效果 → 稳定性三层

指标图从左至右或从上至下固定为三层：

1. **可行性门槛**：完整分配、硬约束违反、资源/路线合法性；任一失败即不可下发。
2. **生产效果**：按时率、平均延迟、最大延迟；优先选择按时率高且延迟低的方案。
3. **计划稳定性**：相对 AP 改配炉次数、资源负载均衡；效果相近时优先少改动。

图末只输出一个“推荐 AQ / 推荐 AR / 人工复核 / 持平”的选择结果，不再并列展示 Frozen。

### 3. 选择算法采用硬约束优先的字典序

先过滤不可行方案；若只有一方可行，推荐可行方；若两方均不可行，推荐人工复核。两方均可行时按以下顺序比较：按时率降序、平均延迟升序、最大延迟升序、相对 AP 改配炉次数升序、资源负载偏差升序。所有指标相同才判定持平。

这样可以避免 Codex 因改动更少而掩盖延误，也避免决策树因完成炉次更多而掩盖硬约束违反。指标图和报告正文都使用同一口径。

### 4. 报告采用短文案和 1.5 倍行距

Word 的 Normal、标题下正文、列表和表格单元格统一设置 1.5 倍行距；首段用一句话结论，随后依次是流程图、指标体系图、真实结果和选择结论。详细审计路径只保留在证据文件中，不在首屏重复展开。

## Risks / Trade-offs

- [Risk] 双线路图过度简化，读者看不出 AQ 和 AR 的输入一致性 → Mitigation：在共同输入节点和图下注明同一 AP、同一事件、同一窗口，且明确 Codex 不读取 AQ。
- [Risk] 只看完成率会忽视延迟和资源扰动 → Mitigation：把完整性/约束设为硬门槛，再比较按时率、延迟和改配规模。
- [Risk] 报告压缩后丢失实验边界 → Mitigation：保留一段短边界说明，明确真实字段、受控压力输入和 `external_api_called=false`。
- [Risk] Word 渲染器对中文字体支持不稳定 → Mitigation：插入 PNG 主图，保留 Markdown 版本；生成后渲染逐页检查布局和图像完整性。

## Migration Plan

1. 基于当前 SVG/PNG 重绘双线路主图，并新增评价指标体系图及截图。
2. 修改报告生成器，设置 1.5 倍行距、短文案和两张插图。
3. 重新生成 Markdown 与 Word 报告，检查 AQ/AR 数值和推荐结果。
4. 运行图形规范检查、报告渲染检查和文本一致性检查。
