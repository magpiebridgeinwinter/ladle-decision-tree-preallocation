## ADDED Requirements

### Requirement: 评价指标体系图必须体现三层判定顺序

评价指标图 MUST 按“可行性门槛 → 生产效果 → 计划稳定性 → 推荐结果”展示；可行性层 MUST 包含完整分配、硬约束、资源/路线合法性；效果层 MUST 包含按时率、平均延迟、最大延迟；稳定性层 MUST 包含相对 AP 改配炉次数和资源负载均衡。

#### Scenario: 观众理解判定顺序
- **WHEN** 观众从左至右或从上至下阅读指标图
- **THEN** 能理解先判断能否下发，再比较生产效果，最后比较改动规模和资源稳定性

#### Scenario: 方案违反硬约束
- **WHEN** AQ 或 AR 在可行性门槛层失败
- **THEN** 该方案直接标记为不可下发，不进入后续效果和稳定性优选

### Requirement: 指标图必须使用真实本次结果作为示例

指标图或其报告截图 MUST 展示 AQ `30/31`、AR `31/31`、AR 改配 3 炉、28 炉保持 AP、规则违反 0；示例不得使用旧版本“4 炉改配”结论。

#### Scenario: 查看真实示例
- **WHEN** 观众查看指标图结果条
- **THEN** 可直接看到 AQ、AR 的完成数和 Codex 的改配/稳定性结果

#### Scenario: 审计结果与图不一致
- **WHEN** 图形数据与当前 audit.json 不一致
- **THEN** 生成流程失败或在校验中报告不一致，不得继续发布报告

### Requirement: 评价指标图必须具备图形可读性

指标图 MUST 遵守 diagram-design 的 16:9、正交连接线、标签避让、无障碍 title/desc 和有限强调色要求；图中节点数量 MUST 控制在 9 个以内。

#### Scenario: 导出截图
- **WHEN** 指标图导出为 PNG 并插入报告
- **THEN** 三层指标、两条方案列和推荐结果均清晰可见，文字不重叠、不截断
