## Context

当前真实数据流程从 PLAN(1) 读取钢包位置码，并在场景构建阶段将位置码转换为调度器使用的数值坐标。项目目录中已有工厂位置字典 `loc_location.xlsx`，但现有预配流程没有把该文件作为输入接入；位置码无法直接转为数字时会退化为默认值，造成距离、到达时间和候选排序失真。

本变更需要跨越数据读取、场景构建、决策树运行、审计输出和工作簿导出多个边界。原始 PLAN 中 `AE` 是工厂历史预配包，现有输出中的 `AO` 是未接入位置映射的决策树基线，`AM` 是扰动后的 LLM 结果；新结果必须单独追加，保证三种口径可追溯。

## Goals / Non-Goals

**Goals:**

- 将 `loc_location.xlsx` 的位置码、坐标、跨区和状态解析为标准化位置记录。
- 在真实 PLAN/CRANE 决策树预配中使用映射后的钢包坐标。
- 对位置映射覆盖率、缺失、重复和无效状态进行审计。
- 重新运行 2026-03 真实 PLAN/CRANE 预配，生成独立的新结果列 `AP`。
- 保留原始 `A:AL`、工厂 `AE`、已有扰动结果 `AM:AO` 不变，并验证这一点。
- 为位置解析、回退策略、预配结果和工作簿追加建立自动化验证。

**Non-Goals:**

- 不把工厂 `AE` 直接当作决策树答案，也不以复制工厂结果替代模型拟合。
- 不在本变更中增加“当前钢包优先”等新的业务评分规则。
- 不重算或覆盖既有 LLM 扰动结果和离线场景数据库。
- 不修改原始桌面数据文件，不上传 `PLAN(1).xlsx`、`CRANE.xlsx` 或 `loc_location.xlsx`。
- 不接入实时生产控制系统。

## Decisions

### 1. 位置字典作为显式输入

新增位置映射读取契约，按 `LOC_LOCATION` 建立唯一索引，至少保留 `SPAN_NAME`、`POS_X`、`LOC_TYPE`、`LOC_STATUS` 和 `GWDMC`。运行入口通过参数或默认路径接收位置字典；缺少文件时明确失败并说明如何指定，而不是静默使用错误坐标。

备选方案是把位置表复制成代码常量。该方案会造成数据版本不可追踪，无法随工厂位置表更新，因此不采用。

### 2. 映射后的坐标优先，缺失时可审计降级

场景构建优先使用位置表 `POS_X`，同时保留原始位置码和映射状态。对于位置码存在但 `POS_X` 缺失的记录，默认运行不把空值伪装成坐标 `0`；记录 `position_mapping_missing`，按当前项目的显式回退策略处理或排除，并在审计中统计。映射成功的记录标记来源为 `loc_location.xlsx`。

备选方案是继续将字符串位置码强转数字并以 `0` 作为默认值。该方案不可解释且会让不同位置碰撞，不采用。

### 3. 重新预配结果追加到 AP

工作簿导出沿用现有 PLAN 工作表，在当前使用范围末尾追加一列：`决策树预配包（接入位置映射）`。每个纳入评测的炉次写入结构化可读文本，至少包含分配状态、钢包号和真实行车号；未分配或被排除时写入原因。第二行写入稳定的英文键 `DecisionTreePreallocationWithLocationMap`。

不修改 `AE`、`AM`、`AN`、`AO`。列名会在结果摘要中解释：`AE=工厂历史方案`、`AO=旧决策树基线`、`AP=接入位置映射后的新决策树结果`。

### 4. 结果必须可复现且可比

运行固定同一批 PLAN/CRANE 数据、同一评测月份和同一决策树版本，输出新的 JSON 审计。审计至少记录位置字典路径、字典行数、映射成功/缺失/无效数量、炉次数、分配成功率、钢包结果与工厂 `AE` 的对照统计。结果对照以炉次主键 `出钢记号-计划顺序号` 对齐。

### 5. 验证顺序

先验证位置读取和关键坐标样例，再运行全量预配；之后检查 `AP` 值、原始列不变、行车编号可追溯、公式错误扫描和工作簿渲染。关键样例包含 `JU6310E7-300770`，用于确认 `4QF5` 的坐标确实进入调度输入。

## Risks / Trade-offs

- [Risk] `LOC_LOCATION` 存在重复位置码或状态为空 → [Mitigation] 运行前检测重复键，审计保留重复/空状态统计；重复键不允许静默覆盖。
- [Risk] 位置表的坐标单位与 PLAN/CRANE 坐标单位不一致 → [Mitigation] 延续项目现有坐标单位契约，在审计记录单位；先用已知 `4QF5=36075`、`2QF5=17230` 做范围校验。
- [Risk] 接入真实坐标后结果与工厂历史方案仍有较大差异 → [Mitigation] 将其作为可量化的模型基线变化报告，不强行宣称复现工厂；后续另立“工厂策略拟合”变更。
- [Risk] 新列文本过长影响工作簿可读性 → [Mitigation] 复用现有结果列样式，限制列宽并使用稳定的短格式，完整细节放入 JSON 审计。
- [Risk] 原始和既有结果列被误写 → [Mitigation] 导出前后对 `A:AO` 做逐单元格一致性检查，并保留副本输出。

## Migration Plan

1. 增加位置字典读取和场景构建参数，补充单元测试。
2. 使用真实 `PLAN(1).xlsx`、`CRANE.xlsx`、`loc_location.xlsx` 运行全量决策树预配。
3. 将新结果导出为 `outputs/PLAN(1)_位置映射决策树预配包结果.xlsx`，同时写出 JSON/摘要审计。
4. 完成表格值、公式、渲染和原始列不变性检查后，供前端或报告引用。
5. 回滚时删除新增输出文件即可；原始工作簿及既有 `PLAN(1)_事故扰动重配包结果.xlsx` 不受影响。

## Open Questions

- 工厂后续是否能提供位置状态、钢包实时状态和位置表版本号，以便将映射从静态字典升级为按时刻快照？
- `LOC_STATUS` 的数值编码和不可用状态是否已有正式业务字典？本变更只做字段保留与审计，不推断其业务含义。
